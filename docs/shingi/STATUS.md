## Етап 1 · ядро (гілка `shingi/stage-1-core`)

Написано: схема БД, парсер, групування, перевірка підписів Telegram, сесії, усі маршрути з розділу 5 брифу (оплата, грамоти, розсилки, питання штабу, налаштування бота — заглушки `501` до етапів 4–5), rewrite у `vercel.json`, тести.

### Що перевірено

- Юніт-тести: 42 з 42 проходять (парсер, групування, підписи Telegram, сесії). Запуск: `npm run test:shingi` (Node 22.18+/24, без `tsx`).
- `tsc --noEmit` (`npm run lint`): без помилок.
- Роутер без бази (фіктивний `DATABASE_URL`): 404/405, 401 без входу і без адмін-токена, 503 без `SHINGI_BOT_TOKEN`, підроблений підпис Telegram → 401.

### Що НЕ перевірено

- SQL проти реальної Postgres (міграція, `ON CONFLICT`, `json_to_recordset`): з сесії немає безпечного доступу до бази. Перший запуск покаже помилки, якщо вони є.
- `curl` по маршрутах на проді: гілка не задеплоєна і не злита в `main`.

### Перевірка після деплою (потрібен адмін-токен сайту)

- `GET /api/shingi/admin/migrate` — створює таблиці, повертає їх список
- `GET /api/shingi/event/current` — `{"event":null}`, поки подія в `draft`
- `GET /api/shingi/admin/events` — одна подія-заглушка

### Потрібно від Ігоря

1. Змінні у Vercel (production + preview + development): `SHINGI_BOT_TOKEN`, `SHINGI_JWT_SECRET` (`openssl rand -hex 32`), `SHINGI_ADMIN_TG_IDS` (ваш Telegram ID).
2. Дозвіл злити гілку в `main` після перевірки (push у `main` = продакшн-деплой).
3. Реальну дату події — щоб замінити заглушку.
