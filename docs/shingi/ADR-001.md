# ADR-001 · Архітектура модуля SHIN GI

Статус: прийнято (етап 1). Автор рішення: Claude Code за брифом `SHINGI-BRIEF.md`.

## План файлів (етап 1)

```
api/_shingi/handler.ts        роутер: path → маршрут, сесія, адмін, помилки (монтується в api/index.ts)
api/_shingi/belts.ts          коди поясів, категорії A/B/C
api/_shingi/grouping.ts       вік на дату, блок kids/open, відра, ключ групи, автосортування
api/_shingi/parser.ts         парсер списку «одним повідомленням»
api/_shingi/auth.ts           підпис Login Widget / Mini App, JWT-сесія, cookie
api/_shingi/admin-auth.ts     адмін: токен сайту, admin_users, Telegram-адмін, перевірка Origin
api/_shingi/db.ts             Pool, CREATE TABLE IF NOT EXISTS, транзакції, shingi_log
api/_shingi/store.ts          події, лічильники, профіль
api/_shingi/routes-public.ts  публічні та тренерські маршрути
api/_shingi/routes-admin.ts   адмінські маршрути
tests/shingi/*.test.ts        node --test (парсер, групування, підписи Telegram)
```

## Рішення

1. **Код модуля в `api/_shingi/`, але виконується всередині існуючої функції `api/index.ts`.** Спершу було зроблено окрему функцію `api/shingi.ts` з rewrite у `vercel.json`, але Vercel відхилив деплой: `exceeded_serverless_functions_per_deployment` — на Hobby-плані максимум 12 функцій, а в `api/` їх уже рівно 12. Тому роутер лежить у `api/_shingi/handler.ts` (файли в `_`-папках функціями не стають), а `api/index.ts` монтує його двома рядками: `app.all('/api/shingi/*', ...)`. Бонус: на ці маршрути діють загальний rate limiter (300 запитів/хв) і перевірка Origin з `index.ts`. Rewrite в `vercel.json` не потрібен — працює загальний `/api/(.*)`. Окремий пул `pg` (max 3) із локальними парсерами типів, щоб не змінювати розбір DATE/NUMERIC в існуючому коді.
2. **Сесія тренера — власна, не зі сторінки адмінки.** httpOnly cookie `shingi_session` із JWT HS256 (claim `pid`, 30 днів). Секрет: `SHINGI_JWT_SECRET` → `SESSION_SECRET` → `AUTH_TOKEN_SECRET`. JWT підписано вручну через `crypto`, нових залежностей немає.
3. **Вхід лише через Telegram, паролів немає.** Підписи перевіряються за офіційним алгоритмом. Токен бота береться лише з `SHINGI_BOT_TOKEN`.
4. **Адмін-доступ трьома шляхами:** Bearer-токен існуючої адмінки сайту (той самий `SESSION_SECRET`), токен із `admin_users` з роллю `admin`, або Telegram-профіль з `SHINGI_ADMIN_TG_IDS` / `is_admin`. Мутації по cookie додатково перевіряють `Origin`/`Referer` (захист від CSRF).
5. **Схема БД створюється при першому виклику функції** (`CREATE TABLE IF NOT EXISTS`, кешований прапорець), плюс ручний `GET /api/shingi/admin/migrate`. Усі таблиці з префіксом `shingi_`.
6. **Оплата** (етап 5): повторно використовуємо інтеграцію Monobank з `api/mono-parent-invoice.ts` і вебхук `api/monobank-webhook.ts`. Платіж ідентифікується `reference = shingi_{event}_{profile}_{ts}_{rand}`. Вебхук має бути ідемпотентним: оновлення за унікальним `reference`, перехід `created/processing → success` лише один раз.

## Перевірка схеми на дірки (system-design)

| Ризик | Як закрито |
|---|---|
| Дублікати бійців | унікальний індекс `(profile_id, lower(full_name), coalesce(birth_date, 1900-01-01))`; масове додавання через `ON CONFLICT DO NOTHING` |
| Подвійна заявка | `UNIQUE (event_id, fighter_id)`; повторна подача оновлює запис, оплачений статус не скидає |
| Гонка за останнє місце | транзакція з `pg_advisory_xact_lock(event_id)` перед підрахунком ліміту |
| Зміна ваги/поясу після оплати | знімок `weight_kg`/`belt` у заявці; правка бійця оновлює лише `draft/submitted` |
| Повторні вебхуки mono (етап 5) | унікальний `reference`, статус змінюється лише вперед |
| Тренер без Telegram | `tg_id` nullable, унікальний лише де не `NULL`; команду створює адмін |
| Втрата ручних правок груп | `group_manual`; автосортування їх не чіпає, поки не передано `reset_manual=1` |
| Вік змінюється з часом | вік рахується на дату події з `birth_date`; `age_years` — запасний варіант |
| Експорт з формулами | комірки, що починаються з `= + - @`, екрануються |

## Наслідки

- В існуючих роутах нічого не змінено. У спільних файлах: імпорт і `app.all('/api/shingi/*')` в `api/index.ts`, скрипт у `package.json`, пункт меню в `src/Admin.tsx`.
- Нові функції в `api/` додавати не можна, доки проєкт на Hobby (ліміт 12). Усе нове для SHIN GI (бот, вебхук) — теж через `api/index.ts` або `api/_shingi/`.
